# Visualization

Choose the smallest visual that makes the requested relationship easier to understand.

## Choose a form

- Use a table for exact comparisons or repeated mappings.
- Use a flow or timeline for sequence and state changes.
- Use a tree for hierarchy or branching.
- Use a chart when quantitative patterns matter.
- Use a diagram when structure, ownership, or dependencies matter.
- Use an interactive HTML explainer when the user needs adjustable inputs, hover details, or exploration.

## Workflow

1. Define the decision or relationship the visual must clarify.
2. Select the simplest suitable form and limit decorative elements.
3. Label axes, units, nodes, controls, and assumptions clearly.
4. Keep colors, type, spacing, and interaction states consistent.
5. Test empty, minimum, maximum, and representative states when the visual is interactive.
6. Check readability at the intended display size and provide a concise explanation of what the user should notice.

## Safety and accuracy

- Do not invent data, labels, or relationships.
- Distinguish measured values, estimates, and user-entered values.
- Preserve keyboard access and visible focus for interactive controls.
- Do not use an interactive surface to hide a simple answer.
